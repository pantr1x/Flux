# Flux – notes for Claude

Flux is a small code editor written in **Rust** (egui) for Windows 10/11 and Linux: one-click Run, Live Server, Claude AI, GitHub, plugins (JavaScript in QuickJS), themes, and it updates itself from the `ci-native` / `ci-native-linux` branches. The old Electron app (`src/`) and the paused Tauri app (`desktop/`) were **removed** (2026-11-14, the user's choice) – the repository is Flux Native only. Comments in the code that say "like Electron Flux / src/main/…" describe where a feature was ported from; that code is in the git history.

## Layout

| Path | What it is |
|---|---|
| `native/` | Flux itself (`flux-native`, egui). Details below. |
| `crates/flux-core` | shared logic: `settings` (`settings.json`), `fsops`, `python`, `runner` (`command_for`), `pty`, `toolchains`. |
| `crates/flux-preview` | Live Server preview helper on Linux (wry/WebKitGTK, its own process). |
| `crates/flux-tools` | developer tool: translations (`cargo run -p flux-tools -- strings | check [--all] | add <file.json> | fmt`) and `review` = the safety review of plugin pull requests (`src/review.rs`, used by `plugin-review.yml`). |
| `crates/flux-site` | the website as a Rust program: `src/page.rs` holds `index.html`, `llms.txt`, `robots.txt`, `sitemap.xml` and `install.sh` as raw strings, `assets/` the images; `cargo run -p flux-site -- <dir>` writes the site. |
| `locales/` | app translations (`<lang>.json` + `index.json` + `en.keys.json`), bundled with `include_str!`. |
| `themes/` | bundled code themes (`*.conf`) and the theme store (`themes/store/`). |
| `plugins/` | plugins for the store (JavaScript, `"native": true` in `index.json`). Guide: `docs/PLUGINS.md`. |
| `.github/workflows/` | `native.yml` (build, tests, smoke/update/memory tests, Defender scan, publish to `ci-native` / `ci-native-linux` incl. `CHANGELOG.md`), `pages.yml` (`cargo run -p flux-site` → `gh-pages`), `plugin-review.yml`, `wiki.yml` (publishes `docs/wiki/*.md`). |

**Everything that is code is Rust** (the user's wish, 2026-11-14): the website and the plugin review were rewritten in Rust. Only `plugins/` (JavaScript – Flux runs plugins in QuickJS), `docs/` and `themes/` are not, and `.gitattributes` keeps them out of GitHub's language stats.

## Flux Native (`native/`, pure Rust + egui)

- **Why:** in a measurement on Windows CI, Electron Flux took ~120 MB and the Tauri/WebView2 build ~109 MB, because the Chromium UI engine is almost all of it. So the user chose a **native** app with a different look, and Flux Native is the way forward. The Electron and Tauri apps were removed from the repository on 2026-11-14; already installed Electron Flux 1.5+ still hands over to Native (`toNative.js` in the released builds).
- **Layout:** Cargo workspace at the repo root (`Cargo.toml`) with these members:
  - `crates/flux-core`: shared logic, used by both Rust builds, with the modules `settings` (same `settings.json` as Electron), `fsops` (incl. `summary(dir)`: files, lines, languages, last change), `python`, `runner` (`command_for`) and `pty`. Events go through an `Emit` callback (`Arc<dyn Fn(&str, Value)>`).
  - `desktop` (Tauri),
  - `native`.
- **`native/src/`:**
  - `app.rs`: the window. It has a top bar with tabs and ▶ Run, a sidebar with projects and a file tree, and one rounded card holding the editor plus Output/Terminal, followed by a status bar. Editing uses `egui::TextEdit` with syntect colors (`egui_extras::syntax_highlighting`) and a line number gutter. It also covers autosave after 1 s, F5, Ctrl+S/O/W and reloading on outside changes via `notify`.
  - `term.rs`: Alacritty's VT emulator (`alacritty_terminal`) fed by `flux_core::pty`, drawn as a colored grid, with keys → bytes. Its event listener (`Replies`) sends the emulator's answers (`Event::PtyWrite`, e.g. to `ESC[6n`) back to the pty in `feed()`: Windows ConPTY (portable-pty uses `PSEUDOCONSOLE_INHERIT_CURSOR`) prints **nothing** until `ESC[6n` is answered – with `VoidListener` every program hung on Windows (fixed in 0.9.15; Linux never asks). Test: `cargo test -p flux-native term_`. `flux_core::pty::spawn()` also has a **waiter thread** (`try_wait` every 50 ms): ConPTY gives the reader no EOF while the pseudoconsole is open, so after the child exits it waits ≤ 300 ms for the reader, then drops `Live` (closes the ConPTY) and emits `exit_ev` – data always comes first; a stale exit after Stop + new run is skipped. Test: `cargo test -p flux-core pty_`. `show()` merges cells with the same colours into one `LayoutJob` section and skips trailing blanks.
  - `theme.rs`: Flux colors, plus Segoe UI and Cascadia Mono from `%WINDIR%\Fonts`.
  - `widgets.rs`: painted sidebar rows, icon buttons, section captions, text with `…`, the logo.
  - `gen.rs`: the file and line icons as SVG (drawn with resvg via egui_extras `svg`; `<text>` in an icon is drawn by egui on top) and the built-in code themes. It was generated from the old Electron `icons.js`/`themes.js`; edit it directly now.
  - `i18n.rs`: `t("…")` / `tf("…", &[("n", "3")])` with the same `locales/*.json` (bundled with `include_str!`, a newer `userData/locales` copy wins). `cargo run -p flux-tools -- strings` collects them (see *Translations*).
  - `app/intro.rs`: the first-run intro (same steps and look as `onboarding.js`: splash, language with flags, name, what to code, extras, look with theme/accent/brightness and a live preview, done). Shown until `settings.onboarded`; `FLUX_INTRO=1` forces it, the `FLUX_TEST` action `next` moves on.
  - `smooth.rs`: smooth scrolling for every `ScrollArea`: call `smooth.begin()` before `show()` (it takes the wheel over the area's layer and returns the offset to set, `None` when idle so the scrollbar works) and `smooth.end()` after. Physics per area (`S`): wheel notches add velocity (`notch × 1.5 / TAU_WHEEL`, 0.30 s, capped 9000 px/s, opposite direction resets) and the view decays exponentially (one notch travels exactly its distance, the rest < 1 px is added at the stop); touchpad deltas move 1:1 while fingers move, their speed is tracked (EMA) and after 50 ms without input it glides on with `TAU_TOUCH` 0.45 s (> 120 px/s); jumps (minimap, search) use a 220 ms Hermite segment. Unit tests: `cargo test -p flux-native smooth`. Off with `inertia` or `optAnim`/`lite`. (The 0.9.9 fling was never committed – it shipped for real in 0.9.12.)
  - `wall.rs`: the Electron look of material `wallpaper`: the desktop wallpaper (`SystemParametersInfoW(SPI_GETDESKWALLPAPER)`, or an own `settings.bg` image, `FLUX_WALLPAPER` in tests) drawn in the background layer, lined up with the desktop, under translucent `--base-alpha` / `--card` panels. Off with `material: none`, `optFx` or `lite`. Overlays (settings, search, menus) use the opaque `Pal.solid`.
  - Animations follow `anim_on()` (`transitions` + `optAnim`/`lite`): hover fades via `animate_bool_with_time`, the gliding active-tab indicator, content fade on file/project switch, the settings open, and the intro (moving glows, logo draw-in, steps slide in).
  - `native/CHANGELOG.md`: release notes of Flux Native, shown in Settings → General → About & updates. Add a section with each bigger change and raise `version` in `native/Cargo.toml` (and `assets/flux.rc`).
  - `mem.rs`: `trimMemory` for Flux Native (K32EmptyWorkingSet 20 s after losing focus, then every 2 min).
  - `build.rs` + `assets/flux.rc`: Windows icon and "Flux" description (Task Manager, taskbar); the window icon is `assets/icon64.png`.
  - `app/chrome.rs`: Flux's own title bar. `glass::no_top_line()` (all windows) subclasses the window proc and undoes winit's `WM_NCCALCSIZE` hack for undecorated windows with shadow (`rgrc.top += 1`, its "1px border on the top") when not maximized – that 1 px strip was the thin line above the top bar (the DWM border color in `glass::round()` was not it). The window has no Windows frame (`with_decorations(false)`). `drag_area()` makes empty parts of the top bar move the window (`StartDrag`, double-click = maximize). `window_chrome()` draws − □ × (46 px each, `CONTROLS_W`) in an `Order::Tooltip` area at the top right, above settings and the intro, plus 5 px resize edges (`BeginResize`). The top bar reserves `CONTROLS_W` on the right (with `sidePos: right` the sidebar toggle moves into the top bar).
  - `live.rs`: Lively Wallpaper / Wallpaper Engine detection, ported from `src/main/liveWallpaper.js` (same files, `tasklist`, `LOCALAPPDATA` / `FLUX_STEAM_PATH` for tests). `App::check_live()` runs it on a thread at most every 10 s while focused; `wall_source()` → `wall::Src::Image` or `Src::Video(file, preview)`. Off with `liveWallpaper: false` or an own `settings.bg`.
  - `wall.rs` video: `Src::Video` plays through Windows Media Foundation (`windows` crate, `IMFSourceReader` with a D3D11 device manager = hardware decoding via `hw_decoder()`, RGB32 scaled to ≤ 960 px, ≤ 24 fps; late frames are skipped without copying and a lag over 0.8 s seeks to the real time) into one texture updated in place; it plays only while focused and `optAnim` is on (`set_playing`). If MF fails (or off Windows) the preview image is shown. Every image also gets a 1/8 box-blurred copy (`blurred()`), drawn under the card with `paint_blurred()` like `backdrop-filter`.
  - Baked copy: `Src::Video` never decodes the original. `baked_copy()` / `bake_now()` make `userData/wallcache/<sha16>.mp4` once (key = path + size + mtime; `video::bake()` = SourceReader RGB32 ≤ 640 px → SinkWriter H.264 1.5 Mbit/s, ≤ 60 s, below-normal thread priority; the newest 3 are kept). While baking, one still frame is shown; if baking fails the still frame stays. Files in `wallcache` are decoded without the D3D11 device. On iGPU laptops the full-size decoder's surface pool was counted as Flux memory (hundreds of MB).
  - `main.rs` has a counting global allocator (`HEAP`, `heap_mb()`), shown in Developer → Memory as *Flux code N MB*. Big files (> 300 KB) get a TextEdit undoer with 20 steps (`undo_capped`).
  - Video in the background: after 3 s paused (`set_playing(ctx, false)`), the MF thread stores the position in `Wall.resume` (100 ns), sets `released` and exits (reader, D3D device and `MFShutdown` freed; the last frame stays). `set_playing(ctx, true)` respawns `video::play(…, resumed: true)` from that position.
  - **Window background** (`material`, Appearance → Window): `see` (*See-through – clear*, the default since 0.9.12), `blur` (*See-through – blurred*), `wallpaper` (*Wallpaper picture*, Flux draws the wallpaper / live wallpaper copy), `none`. `see`/`blur` create the window with `with_transparent` (`main.rs` → `want_transparent()` = material see/blur + `optFx` + not safe mode, independent of Lively), `clear_color` is transparent, `wall_source()` returns `None` and live wallpaper detection is skipped (`App::see_through()`). `glassDim` (default 45) is the base fill alpha; panels keep `cardAlpha` (default 0.94 when see-through). `blur` calls `glass::blur()` (`SetWindowCompositionAttribute` `ACCENT_ENABLE_BLURBEHIND`, loaded at runtime from user32; works on borderless windows on Windows 10/11) in `App::new`; switching clear ↔ blurred applies at the next frame (`glass_apply`), switching from/to wallpaper needs a restart (*Restart Flux* row). `see_migrate()` switches `auto`/`wallpaper` without an own `bg` image (and the old `liveWallMode: glass`) to `see` once (`seeMigrated`).
    - No confirmation dialog any more (0.9.13 removed the `glassTrial` / `GLASS_OK` trial; leftover keys are deleted by `see_migrate()`). A transparent window also gets `glass::no_frame()` (`DWMWA_NCRENDERING_POLICY` = disabled, so DWM's own − □ × don't show through the translucent top bar). Since 0.9.21 `glass::round()` asks DWM for round corners (`DWMWA_WINDOW_CORNER_PREFERENCE` = round) and no 1 px border (`DWMWA_BORDER_COLOR` = none – it showed as a light line across the top), and while transparent and not maximized (`App.rounded`) the panels have no fill (`base_fill()`) and `p.base` is painted once as a radius-8 rect on the background layer, so the corners are round even where DWM doesn't clip. Since 0.9.17 `window_chrome()` draws no backing block: each button is `TOP_H` tall and hovers as a rounded 38×30 pill (radius 8, red for ×), like ▶ Run (the user disliked the square backing).
  - **Live wallpaper modes** (`liveWallMode`, only with `material: wallpaper`): `play` / `still`; the old `see` / `glass` values are gone (migrated).
    - `still`: `Src::Still` decodes one frame, then drops the reader and D3D.
    - `play`: the MF video path.
  - `settings.liveCache` stores the last detection (`sync_live_cache()`). It is used from the first frame, and without a cache the desktop wallpaper waits up to 2 s for the first detection, so it never flashes. `FLUX_LIVE_TEST=1` skips the "is Lively running" check (the CI memory runs with a fake Lively folder).
  - **Back/forward:** `place()` = `home` / `proj:<dir>` / `file:<path>`; `track_place()` records changes at the end of each frame, `go()` restores them. Mouse buttons 4/5 and Alt+←/→ work everywhere; `FLUX_TEST` actions `back` / `fwd`.
  - `update.rs`: self-update. `native.yml` writes `native.json` (`version`, `sha`, `sha256`, `size`) next to `Flux-Native.exe` in `ci-native`; `build.rs` bakes `GITHUB_SHA` as `FLUX_SHA` (`dev` locally = updates off). A different `sha` = newer build. `curl` downloads to `<exe>.new`, the sha256 is checked, *Restart to update* spawns the downloaded `.new` as a helper (`--apply-update <pid> <exe> [--relaunch args…]`, `apply_update()`): it waits for Flux to exit, copies the exe to `.old`, **writes itself over the exe in place** (same file, so a taskbar pin keeps working – renaming the running exe made Explorer move the pin to `.old`, which was then deleted) and starts it with `--updated` (that start deletes `.new` with retries); if the exe stays locked for 10 s it falls back to renaming it to `.old-<secs>`. Closing with a ready update only swaps (no `--relaunch`). `cleanup(true)` at start removes only `.new`; `.old` stays until the new build has run 10 s (`cleanup(false)` from `ui()`). The panic hook in `main.rs` writes `userData/flux-native-crash.log`, shows a MessageBox, and within 20 s of start `rollback()` runs `.old --apply-update … --relaunch --rolledback` the same way (it writes itself back and starts); only in a start with `--updated` and never with `--rolledback`, so a failure the update did not cause (e.g. graphics) cannot swap versions in a loop; the relaunch drops `FLUX_TEST` (same when both renderers fail). `FLUX_TEST` action `panic` tests it. Checks at start and every hour (`autoUpdate` = download by itself, and install by itself once the window has been unfocused for 60 s with nothing dirty/running: `install_with(true, ["--background"(, "--minimized")])`). `cleanup(false)` (10 s after start) must never delete `.new` – before 0.9.2 it did, so fast downloads were lost. `run_check()` also runs while `Ready`: without `.new` it checks normally, with `.new` it downloads a newer `sha` over it (before 0.9.6 a Ready state blocked every later check). **Delta updates:** `native.yml` downloads the previous `ci-native` build and runs `Flux-Native.exe --make-patch <old> <new> out\Flux-Native.patch` (zstd with the old exe as ref prefix, level 19, window 2^26, long-distance matching); `native.json.patch = {from: <old sha>, sha256, size}`. `try_patch()` uses it when `patch.from == SHA`, checks the result's sha256 and otherwise falls back to the full exe. Test: `cargo test -p flux-native patch_roundtrip`. UI: About & updates + status bar chip. Test with `FLUX_UPDATE_URL=http://localhost:PORT/` (a folder with `native.json` + `Flux-Native.exe`) and `FLUX_TEST` actions `update`, `update-get`, `update-install`.
  - **One Flux (`migrate.rs`, `single.rs`, Electron `src/main/toNative.js`):** Electron 1.5+ hands over to Native: `toNative.start()` at the top of `app.whenReady()` (Windows, packaged, not `FLUX_NO_NATIVE`, not `--background`) uses `settings.nativePath` (written by every Native start, `remember_path()`) or `%LOCALAPPDATA%\Programs\Flux Native\Flux-Native.exe`. If present: before migration it spawns `--migrate <pid> <Flux.exe>`, afterwards (`settings.migratedFromElectron`) it just starts Native with the file argument – Electron stays installed as a **launcher**, so its file types / "Open with Flux" keep working – and quits. Otherwise it downloads `native.json` + exe from `ci-native` (sha256 + size, ≤ once a day via `nativeTry`) and migrates on `will-quit` with `--no-window`. `FLUX_NATIVE_URL` points the download at a test server (off Windows it only logs). Native `--migrate` (in `main()`, before the window): waits for the pid, `pins::retarget()` repoints `.lnk` files whose target is the old `Flux.exe` (icon too, and clears `PKEY_AppUserModel_ID` = Electron's `dev.flux.ide`, else the window would not join the pin), sets `migratedFromElectron` + `nativeSeenVersion: 0.9.14` (What's new explains the move once, `migratedSeen`). **Never write file associations to the registry or delete other programs from Native:** 0.9.18/0.9.19 did (HKCU `Flux.<ext>\shell\open\command`, Electron folder + Uninstall key) and Windows Defender quarantined Flux-Native.exe as a trojan (`!ml`), breaking the user's pin. Since 0.9.29 also **no `TerminateProcess` of other processes and no scanning/rewriting of shortcuts at start** (`kill_ghosts`, `kill_if_flux` and `pins::repair` were removed after another `!ml` quarantine); a running Flux without a visible window simply doesn't take over a start (`single::forward()` checks `has_visible_window`), and `pins::retarget()` runs only for `--migrate`. CI `native.yml` scans the build with `MpCmdRun -Scan -ScanType 3` (exit 2 = threat → no publish). Single instance (in 0.9.18 a windowless ghost answered and Flux never opened – since 0.9.29 `forward()` skips a process without a visible window instead of killing it; after the hand-over `boot::bring_to_front(pid)` restores/foregrounds the running window, since a minimized egui window doesn't process events): `single::forward()` sends the file argument (or just focus) to the running Native via `127.0.0.1:<port>` from `userData/flux-native-ipc.json` and exits; `listen()` turns it into `ipc:open` → `open_external()` + focus. CI `native.yml` **Migration test** fakes an Electron install and a link, checks the link moved, the old Flux was **not** deleted, and the second-start hand-over. Release order: Native first (CI green), then the Electron version (only with the user's OK).
  - `pins.rs`: only `retarget()` for `--migrate` (repoints `.lnk` files of the old Electron Flux); no repair at start since 0.9.29.
  - CI `native.yml` **Update test**: copies the build to `Flux-Native(18).exe`, a `.lnk` to it and one to `.old`, serves a fake `native.json` (`sha: ci-update-test`) with `python -m http.server`, runs `FLUX_TEST=update;update-get;update-install` and fails (no publish) unless the relaunched `--updated` process has a window, the file id and sha256 are right, `.new` is gone and `Flux.lnk` points at the exe and the other link is left untouched.
  - `server.rs`: Live Server. It is a tiny std-only HTTP server on `127.0.0.1:5500+` over the project, or the file's folder.
    - Every HTML page gets a script that polls `/__flux/ver` and reloads when the number changes. `save()` and `fs:changed` call `bump()`.
    - HTML/CSS files (and JS with an `index.html` next to it) show **Live Server** instead of ▶ Run (`is_web_file()`), and running starts `live_server()`.
    - The single top-bar button turns into **Stop** while a program or the server runs, and the address chip reopens the page.
    - Test: `FLUX_TEST='1:open=index.html;2:run'` + `curl 127.0.0.1:5500/`.
  - **Live Server since 0.9.32:** the page polls `/__flux/ver?v=N` as a long poll (the server answers when the number changes, ≤ 20 s), `set_live` is pushed every 40 ms. `server::annotate()` adds `data-flux-l="<source line>"` to every opening tag (not html/head/script/style/meta/link/title/base; skips comments and script/style bodies); the injected script (placed right after `<head>`, `inject()` – not at the end, because a half-typed tag would swallow it and show it as text) reports the hovered line to `/__flux/hover?p=<path>&l=N`, `Server::hover()` → `App.hover_src` (file key, line) → an accent band in the editor (`hov` shape) and a scroll to the line when it is off screen (`hover_new`). `preview.rs` has tabs (`Preview.tabs/active`, `tab_title()`): wry `with_new_window_req_handler` pushes `target=_blank` links into `Preview.go` (→ new tab), `with_navigation_handler` records the current URL in `Preview.cur` (own-origin pages stay in the panel, other websites open in the browser); the panel repaints every 80 ms while the WebView exists. Tests: `cargo test -p flux-native server_`.
  - `app/preview.rs`: the Live Server panel on the right of the card (`App.preview`, draggable width; toolbar with address, Full/Tablet/Phone, reload, open in browser, ×).

The background glows move only for 8 s after opening and only while focused (then no repaints while idle).
  - **Auto indent (0.9.38):** `editing::enter()` (Enter consumed in `app.rs` next to Tab handling when no suggestion popup is open, setting `autoIndent`, default on): copies the line's indent, +4 spaces after `{([`, an opening non-void HTML tag or a Python `:`, splits `{|}` / `<ul>|</ul>` into three lines, and empties a whitespace-only line. Tests: `cargo test -p flux-native editing_enter`.
  - `lint.rs`: error hints (`lintHints`, default on). `check(lang, text, python)` runs on a thread 600 ms after `Hl.gen` changes (`App::lint_tick`, results `lint_res` per path, stale gen hidden). Python = real `compile()` via the found Python (`python -I -c`, JSON out) with friendly texts (`explain_py`), JSON = serde_json, others = built-in checks (brackets/strings/comments per `Syntax::of`, conservative missing `;` for C/C++/Java/C#/JS, CSS `;`, HTML tags). A typed closing `)]}"'` that already sits at the cursor only steps over it. Tests: `cargo test -p flux-native complete_`. Popup rows use `Sense::CLICK` (not `click()`): egui makes a focused clickable widget "click" on Space/Enter, which accepted a suggestion on Space (0.9.44); an exactly typed keyword/builtin (`str`) stays in the list, only the file's own word being typed is hidden. Popup: 60 items, `SUG_ROWS` = 10 visible (`Sug.top`, wheel + arrows), doc box for the selected item (`Item.doc`). Accepting `attr="$0"` sets `sug_again` (values open at once). The editor's `EventFilter.escape = true`, so Esc never unfocuses it (egui dropped focus on Esc before our handler). ## Conventions

- **UI text is English and always goes through `t("…")` / `tf("…", &[("n", "3")])`** (`native/src/i18n.rs`).
- **Code comments are in Slovak**, short, like the surrounding code.
- Settings: `self.get(key)` / `self.set(key, value, ctx)` / `update_settings()`; defaults in `prefs.rs` `default_of()`.
- Icons: `widgets::icon_at(ui, pos, size, name, color)` with the SVGs in `native/src/gen.rs` (edit them there – the old generator from Electron's `icons.js` is gone).

## Translations

All 9 languages are bundled (`include_str!` in `i18n.rs`); a newer `userData/locales` copy wins. **`locales/<lang>.json` are the source now** (the old `scripts/locales_*.py` + `build-locales.py` were replaced by `flux-tools`). Adding strings:

1. Use `t("New text")` in Rust code.
2. `cargo run -p flux-tools -- strings` → updates `locales/en.keys.json` (it scans `t(`/`tf(`, `Row::…("key", "Title", "Hint")`, section titles `("Title", vec![` / `pick(`, `prefs.rs` `TABS`, `keymap.rs` labels).
3. Write a JSON file `{"sk": {"New text": "…"}, "de": {…}, …}` for all 8 languages (sk, de, es, fr, it, pl, pt, uk) and run `cargo run -p flux-tools -- add that.json` (sorted, indent 1, checks `{placeholders}`).
4. `cargo run -p flux-tools -- check` must show `chýba 0` for every language (CI runs it in the Linux job).

## Website (GitHub Pages)

- Source: `crates/flux-site/src/page.rs` (the page `INDEX` as one raw string – plain HTML/CSS/JS inside, no dependencies) + `crates/flux-site/assets/` (`icon.png`, `images/*.png`, `images/icons/*.svg`, also used by `README.md`). Edit the HTML inside the raw string; `cargo test -p flux-site` checks that it builds.
- Deploy: `pages.yml` runs on every push that touches `crates/flux-site/**` (any branch) or by hand (*Actions → Website → Run workflow*). It builds the site with `cargo run -p flux-site -- out` and force-pushes `out/` to the **`gh-pages`** branch. GitHub Pages must be set once to *Settings → Pages → Deploy from a branch → `gh-pages` / (root)*. Address: https://pantr1x.github.io/Flux/
- The page is styled like the Flux app itself (top bar = window tabs, home-screen stats and action cards, a live editor window, status bar). Colors are CSS variables in `:root`.
- **Downloads and versions:** buttons point to `https://github.com/pantr1x/Flux/raw/ci-native/Flux-Native.exe` (Linux: the `install.sh` command + Copy button), version/size come from `ci-native/native.json` (`ci-native-linux` on Linux), and the *Releases* list is built from the `CHANGELOG.md` that `native.yml` publishes next to the program (fallback: `native/CHANGELOG.md` on the default branch), sections `## x.y.z`, `md()`. Nothing on the page changes for a new version.
- **Screenshots** (`crates/flux-site/assets/images/*.png`, also used by `README.md`) are real Flux Native windows: a demo project + `FLUX_TEST` (`open=…;run`, `start`, `plugin-store`, `settings=appearance;theme-store`) under `xvfb-run -s "-screen 0 1440x880x24"`, `FLUX_SIZE=1440x880`, `FLUX_PREVIEW_HELPER=target/release/flux-preview` for Live Server, `FLUX_PLUGIN_REGISTRY=plugins`, `FLUX_THEME_REGISTRY=themes/store`, `material: wallpaper` + `seeMigrated: true` + `FLUX_WALLPAPER`; move the pointer to a corner before `import` (tooltips). `og.png` = ImageMagick composite (indigo gradient, Inter from `native/assets/fonts`, editor shot).
- **SEO / GEO**:
  - `<head>` carries the description, canonical, Open Graph and Twitter tags, plus JSON-LD (`SoftwareApplication`, `WebSite`, and a `FAQPage` whose Q&As must match the `#faq` section).
  - `crates/flux-site/assets/images/og.png` (1200×630) is the link preview, and its URLs are absolute.
  - The site also serves `robots.txt`, `sitemap.xml` and `llms.txt`, a plain summary for AI assistants.
  - Platforms: Windows and Linux are available, macOS is *coming soon* (the `.platforms` chips, FAQ, JSON-LD, footer, og.png, llms.txt). Update them when a new platform ships.
- **Scrolling**:
  - The wheel moves a target, and the page eases toward it exponentially (`1 - exp(-dt/95)`). Touchpad and keyboard scrolling stay native.
  - Keep scrolling cheap: the background `.wall` is plain radial gradients on its own layer, and cards have no `backdrop-filter`. Blur filters there made scrolling stutter. Only the sticky top bar blurs.
- Content lives in arrays in the script at the bottom: `FILES` (files in the demo editor: tokens per line + what *Run* prints), `FEATURES`, `LANGS`, `KEYS` (shortcuts). Edit those to change the page.

## Plugins

See `docs/PLUGINS.md` (+ `docs/flux.d.ts`). The store is `plugins/index.json` (only entries with `"native": true` – Electron-only plugins were deleted with the Electron app) + one folder per plugin (`plugin.json`, `main.js`, `icon.svg`, README). Nothing is installed by itself; Native downloads a plugin from GitHub only on **Install** (`FLUX_PLUGIN_REGISTRY=<folder>` for tests). Native's own install scan is `plugins::scan()` in Rust; pull requests are reviewed by `plugin-review.yml` → `flux-tools review` (`crates/flux-tools/src/review.rs`: rules, folder/`plugin.json`/`index.json` checks, Claude `claude-opus-5-5` over raw HTTP with `curl` + structured output + `fallbacks: "default"`, key via curl config on stdin; without the `ANTHROPIC_API_KEY` secret the check asks for a manual review). Plugin PR code is only read, never run.
